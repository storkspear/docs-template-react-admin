# 화면 가이드

`nav.tsx`(`NAV_ITEMS`)에 등록된 화면 9개예요. 각 화면이 무엇을 보여주는지, 어떤 API 를 쓰는지, 모바일에서 어떻게 달라지는지를 정리했어요.

> 컬럼 정의·필터 폼 등 실제 코드는 각 화면 이름으로 `src/pages/`에서 바로 찾을 수 있어요 (예: 대시보드 → `src/pages/DashboardPage.tsx`).

---

## 1. 대시보드 (`/`)

전사 KPI 카드(총 사용자·신규·DAU·MAU·매출·실패)와 대표 앱의 매출 추이 차트, 앱별 지표 미니그리드를 보여줘요.

- **API**: `GET /dashboard/metrics?window=30d` (카드 + 앱별 표), `GET /analytics/revenue?slug={첫 앱}&interval=day` (매출 차트 — `analytics` 계약은 slug 스코프라 "대표 앱" 기준으로만 그려요)
- **모바일**: 앱별 지표 표(`AdminMiniGrid`)가 카드 목록으로 전환돼요. 행 수가 적어 페이지네이션·무한스크롤은 없어요.

## 2. 앱 (`/apps`)

등록된 앱(슬러그) 목록을 사용자 수·활성 구독 수와 함께 보여줘요. 행을 클릭하면 앱 상세로 이동해요.

- **API**: `GET /apps`
- **모바일**: 카드 목록으로 전환. 마찬가지로 앱 개수가 적어 페이지네이션 없음.

## 3. 사용자 (`/users`)

앱을 먼저 고른 뒤 그 앱의 사용자 목록을 검색·조회해요. 앱 상세의 사용자 탭과 같은 컬럼·드로어를 최상위 메뉴로 뺀 화면이에요(둘 다 `userColumns` 공유).

- **API**: `GET /apps/{slug}/users?query=&page=&size=`, `GET /apps/{slug}/users/{userId}` (드로어)
- **모바일**: PC 는 필터가 그리드 위 인라인 바, 모바일은 제목 옆 "필터" 버튼 → 풀스크린 모달. 목록은 무한스크롤 + 카드 목록으로 전환(`useAdminList` 가 PC=페이지네이션/모바일=무한스크롤 자동 분기).

## 4. 분석 (`/analytics`)

앱 하나를 골라 지표 카드(사용자·DAU·MAU·매출·프리미엄·활성구독), 운영 신호(갱신 실패율·웹훅 미처리·리텐션 D1/D7), 시계열 차트(DAU·신규가입·매출)를 보여줘요.

- **API**: `GET /apps/{slug}/metrics`, `GET /apps/{slug}/ops`, `GET /analytics/{metric}?slug=&interval=day` (`metric` = `dau`/`signups`/`revenue`, 3번 호출)
- **모바일**: 카드 그리드가 세로로 쌓여요. 목록형 화면이 아니라 무한스크롤·필터 모달은 없어요.

## 5. 감사로그 (`/audit-logs`)

관리자·시스템 액션 로그를 slug·actor 이메일·action·result·기간으로 필터링해서 봐요.

- **API**: `GET /audit-logs?slug=&actorEmail=&action=&result=&from=&to=&page=&size=`
- **모바일**: 제목 옆 "필터" 버튼(적용 개수 배지) → 풀스크린 모달(RangePicker 포함, 모달 내부에 팝업 렌더). 목록은 무한스크롤 + 카드 목록.

## 6. 발송 (`/send`)

앱별로 푸시/이메일을 작성해서 보내는 화면이에요. 채널(푸시/이메일) 토글 + 대상 앱 + 수신 대상(전체/프리미엄/무료) + 제목/내용 폼.

- **API**: 없음 — 데모예요. 제출하면 토스트만 뜨고 실제 발송은 안 해요. 파생 레포에서 실제 발송 API 로 연결하세요.
- **모바일**: 폼이 세로 스택으로 쌓이는 것 외 특별한 모바일 분기는 없어요.

## 7. 역할·권한 (`/roles`)

역할 목록(소유자/관리자/지원/뷰어)과 각 역할의 설명·권한·멤버 수를 보여줘요.

- **API**: 없음 — 하드코딩된 데모 데이터(`ROLES` 상수)예요. "역할 추가"/"수정" 버튼도 토스트만 띄우는 스켈레톤. 파생 레포에서 실제 RBAC API 연결 필요.
- **모바일**: 별도 카드 전환 없이 `antd Table`이 가로 스크롤(`scroll={{ x: 'max-content' }}`)로 대응.

## 8. 설정 (`/settings`)

계정 정보(이메일 표시), 테마(라이트/다크 — 실제 동작), 표 밀도, 알림 토글을 보여주는 "폼 페이지" 표준 레퍼런스예요.

- **API**: 없음. 테마 모드만 `useThemeMode`로 실제 동작(localStorage 지속). 나머지(표시 이름·표 밀도·알림 토글)는 스켈레톤이라 저장해도 유지 안 됨.
- **모바일**: 최대폭 컬럼이 화면 폭에 맞춰 줄어들 뿐 별도 분기 없음.

## 9. 컴포넌트 (`/components`)

이 템플릿이 제공하는 색·타이포·버튼·폼 입력·탭·태그·피드백·Statistic/차트를 한 화면에 모은 디자인 시스템 갤러리예요. 파생 레포가 재사용 가능한 UI 조각을 한눈에 확인하는 용도.

- **API**: 없음.
- **모바일**: 섹션이 세로로 쌓이고 `Space wrap`으로 요소가 줄바꿈돼요.

## 메뉴 밖 라우트

| 라우트 | 화면 | 비고 |
|---|---|---|
| `/login` | `LoginPage` | `POST /auth/login`. Mock 모드에서만 로그인 폼에 데모 자격증명이 채워짐(`admin@example.com` / `password`) |
| `/apps/:slug` | `AppDetailPage` | 위 "3. 앱 상세" 참고 — `nav.tsx`에 `label` 없이 등록 |

## 공통 패턴

- **목록형 화면** (사용자·감사로그·앱 상세의 사용자 탭)은 `GridPage` + `AdminDataGrid` + `useAdminList` 조합이에요. PC 는 그리드 위 인라인 필터 바 + 하단 페이지네이션, 모바일은 "필터" 버튼(풀스크린 모달) + 카드 목록 + 무한스크롤로 자동 전환돼요.
- **참조형 표** (대시보드 앱별 지표, 앱 목록)는 행 수가 적어 페이지네이션이 필요 없는 `AdminMiniGrid`를 써요 — 모바일에선 카드 목록으로만 전환되고 무한스크롤은 없어요.
- 새 화면을 추가하는 방법은 [`derived-repo.md`](./derived-repo.md)의 "화면 추가 패턴" 참고.
